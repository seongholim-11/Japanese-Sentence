# 02. 화면·퀴즈·검색 일본어화 (M2)

전제: `00` 컨텍스트를 읽었고 `01`이 끝나 샘플 데이터로 앱이 실행된다. 일본어 글꼴 선택(Noto Sans JP 또는 IBM Plex Sans JP)은 사용자가 확정했거나, 네가 추천안을 제시하고 사용자가 승인했다.

````
M2 단계를 진행해 줘. 목표는 "일본어 학습에 맞는 화면(읽기 표시, 일본어 글꼴), 퀴즈, 검색을 완성하는 것"이야. 콘텐츠는 아직 샘플이야.

# 입력
- docs\01-기획문서.md 6장(일본어에서 새로 필요한 것), docs\03-기술-변경-목록.md 3~4장
- 영어 앱에서 얻은 교훈(docs\02 6장)

# 작업

## A. 글꼴
1. 일본어 글꼴 패키지를 설치하고(패키지 이름·버전 존재 여부를 npm 으로 확인한 뒤 `npx expo install` 사용) App.tsx 의 글꼴 로딩·폴백(fontState)에 추가해. 로딩 실패·시간 초과 시 기본 글꼴로 시작하는 기존 동작을 유지해.
2. Txt 컴포넌트가 텍스트 종류(한국어 UI / 일본어 학습 텍스트 / 숫자)에 맞는 글꼴을 쓰게 해(예: `jp` prop). 한자가 한국어 글꼴로 그려져 모양이 달라지지 않게 일본어 텍스트는 항상 일본어 글꼴을 쓰고, 웹에서 `lang="ja"` 를 줄 수 있으면 줘.

## B. 읽기(후리가나) 표시
3. progress.ts 의 prefs 에 `reading: 'always' | 'after' | 'hidden'` 를 추가해(기본 'after'는 DECISIONS.md 값). 기본값·sanitize 검증·백업 가져오기 검증·설정 UI(학습 또는 화면 페이지)를 모두 넣어. 검증 스크립트(깨진 값이 와도 기본값으로 복구)도 갱신해.
4. StudyScreen: 앞면은 표기를 크게. 읽기는 설정에 따라 ① 앞면에 항상 ② 뜻 보기 후에만 ③ 숨김. 뒷면에는 읽기·뜻·예문·예문 읽기(설정 따름)·note 를 보여 줘. 가나 덱은 `reading`(로마자) 대신 한글 독음 안내를 보여 주고 "대략적인 안내" 한 줄을 붙여.
5. DialogueScreen: "영어 가리기"를 "일본어 가리기"로, 말풍선에 읽기 한 줄(설정 따름). 전체 듣기·표현 설명은 유지. 읽기 줄이 더해져 말풍선이 높아지므로 작은 화면(320×568)·글자 최대에서 레이아웃이 깨지지 않게 minHeight 위주로 조정해.
6. 예문 읽기 줄은 폰트 크기를 본문보다 작게, 색은 muted.

## C. 퀴즈 재설계 (src/quiz.ts)
7. 영어 전용 로직(영어 정규식 빈칸, 영어 단어 풀)을 제거하고 아래 유형을 만들어. 세트당 최대 10문제는 유지.
   - 뜻 고르기: 표기 → 한국어 뜻(보기 4개)
   - 읽기 고르기: 표기(한자 포함 단어만) → 히라가나 읽기
   - 한→일 고르기: 한국어 뜻 → 표기
   - 빈칸: 카드에 `blank` 가 있을 때만. 예문에서 `blank` 를 빈칸으로 바꾸고 보기 4개(같은 품사·같은 레벨의 다른 단어의 활용형은 만들 수 없으니 **같은 덱의 다른 카드의 blank 값**을 오답으로 쓴다).
   - 가나 덱: 문자 → 한글 독음 고르기, 독음 → 문자 고르기.
   - 문장 덱: 한국어 → 일본어 문장 고르기(오답은 같은 level·style 문장).
8. 오답 보기 규칙(영어 앱에서 겪은 문제): 보기 문구가 서로 같지 않게, 정답과 뜻이 쉼표 항목 단위로 겹치지 않게(영어 앱의 overlaps 방식 재사용), 읽기 고르기에서는 같은 읽기가 두 번 나오지 않게(동음이의어), 빈칸 오답이 예문에 이미 들어 있는 글자가 아니게.
9. 카드 수가 4장 미만인 세트(작은 세트 크기)에서도 오류 없이 문제를 만들고, 보기가 부족하면 같은 덱 전체에서 보충해.
10. 검증 스크립트(Node, TypeScript 를 transpile 하는 방식 — 영어 앱 scripts 를 참고): 모든 세트 크기(10/20/30/50/100) × 모든 덱 × 수십 라운드로 문제를 생성해 ① 예외 없음 ② 보기 4개·중복 없음 ③ 정답 위치 정확 ④ 빈칸 일치 ⑤ 뜻 겹침 없음을 확인.

## D. 검색 (src/search.ts)
11. 표기·읽기·한국어 뜻·예문으로 검색. 입력을 NFKC 정규화하고, 히라가나/가타카나를 같은 글자로 취급해. 히라가나로 검색하면 한자 단어(reading 일치)가 나오게. 앞에서 시작하는 일치를 먼저, 최대 60건(기존 규칙).
12. SearchScreen 결과에 읽기를 같이 보여 주고, 안내 문구("단어, 뜻, 문장 검색")를 일본어 앱에 맞게.

## E. 음성 연결
13. speech.ts: 기기 음성 대체의 language 를 `ja-JP` 로. `speakText`(어떤 문자열을 읽을지)는 05 단계 결정(표기 vs 읽기)에 따라 쉽게 바꿀 수 있게 한 함수로 모아 둬(지금은 표기 기준).

# 검증
- typecheck, 위 검증 스크립트, 저장값 검증 스크립트(깨진 값·옛 형식), 브라우저 확인: 375×667 과 320×568, 글자 크기 "아주 크게", 읽기 설정 3가지에서 학습·대화문·퀴즈·검색 화면이 깨지지 않는지 스크린샷으로 확인.
- 콘솔 오류(특히 React 경고) 0건.
````
