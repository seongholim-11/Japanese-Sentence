M6 단계를 진행해 줘. 목표는 "일본어 앱을 앱스토어에 제출할 수 있는 상태로 문서·사이트·이미지를 준비하는 것"이야. 영어 앱의 출시 자료(D:\personal_project\English-Sentence\docs\store-listing.md, docs\release-guide.md, site\, docs\store-previews\)를 읽기 전용으로 참고해 구조와 품질 기준을 그대로 따라.

# 작업

## A. 사이트 (GitHub Pages)
1. site\index.html, site\support\index.html, site\privacy\index.html 을 일본어 앱 기준으로 다시 써. 개인정보처리방침은 실제 동작(수집 없음, 기기 안 저장, 백업, 알림, 포함된 합성 음성과 기기 음성 대체, 외부 자료 출처)과 일치해야 해. 지원 페이지는 자주 묻는 질문(요금, 오프라인, 음성·알림 문제, 기록 백업, 읽기 표시 설정)과 문의 방법(GitHub 이슈, 개인 정보 적지 말라는 안내)을 포함해. 공개 페이지에 개인 이메일을 넣지 마.
2. .github\workflows\pages.yml 은 site\ 폴더만 배포하게(앱 웹 버전은 올리지 않음). src\links.ts 의 URL 을 새 저장소 주소로. 새 GitHub 저장소 생성·Pages 설정·푸시는 사용자가 직접 하거나 요청할 때만 해.

## B. 스토어 문구 (docs\store-listing.md)
3. 이름(30자 이하), 부제(30자 이하), 프로모션 텍스트(170자 이하), 키워드(100자 이하, 이름·부제와 겹치지 않게), 설명(4,000자 이하), 이 버전의 새로운 기능, 카테고리, 저작권, 지원/방침 URL. 글자 수를 스크립트로 세어서 제한 안인지 확인해. 카드 수·기능 설명은 실제 데이터와 일치해야 해(숫자를 스크립트로 세어 넣어). 과장·허위 주장(JLPT 공식, 합격 보장 등)은 쓰지 마. JLPT 레벨은 "비공식 구분"임을 설명에 밝혀.
4. 연령 등급 설문 답변표: 예문·대화문 전체를 키워드로 훑은 결과(비속어·술·담배·약물·폭력·성적·공포·도박)를 근거로 정직하게 정리하고, 목표 등급은 DECISIONS.md 값. 외부 상표·실존 인물 언급 점검.
5. 심사 메모(로그인 불필요, 오프라인 음성, 알림 권한 시점), 앱 개인정보("데이터를 수집하지 않음"), 수출 규정(ITSAppUsesNonExemptEncryption false).

## C. 이미지
6. 스크린샷·미리보기 이미지·헤더·검색 결과 이미지 규격(최신 Apple 문서에서 확인): iPhone 6.9형 1320×2868, iPad 13형 2064×2752, 헤더 3840×1646(21:9)·검색 결과 3840×2560(3:2)(안전 영역 안에 핵심 요소, 알파 채널 없음), 유니버설 5244×2950 PNG. 사용자가 어느 업로드 칸에서 어떤 크기를 요구하는지 알려 주면 그 크기로 만들어. 영어 앱의 제작 방식(HTML/CSS + 실제 앱 스크린샷 합성, 헤드리스 브라우저 캡처, 한글·일본어 글자는 AI 이미지 생성기로 그리지 않기)을 그대로 따라.
7. 앱 화면 캡처는 예시 데이터를 넣은 상태로 하되 실제 앱 화면이어야 해(웹 캡처는 상태바가 없음 — 가능하면 TestFlight 실기기 캡처로 교체를 권장). 일본어가 보이는 화면(읽기 표시, 대화문, 퀴즈)을 중심으로.

## D. 출시 가이드 (docs\release-guide.md)
8. 영어 앱 가이드를 일본어 앱 기준으로: 앱 등록 칸별 값, `eas init`(새 프로젝트) → `eas build --platform ios --profile production` → `eas submit`, TestFlight 점검표(무음 모드·비행기 모드 음성, 알림, 작은 iPhone 큰 글자, 읽기 표시 3가지, 백업, 한 손 조작), 거절 사유 대비, 업데이트 방법, 알려진 한계.
