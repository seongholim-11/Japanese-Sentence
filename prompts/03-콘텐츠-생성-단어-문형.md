콘텐츠 생성 작업이야. 이번에 만들 것: 〈덱: kana | words | patterns〉, 〈레벨: N5 | N4 | N3 | 해당 없음〉, 〈개수: 예 100장〉 (한 번에 50~100장씩 배치로 나눠서).

# 먼저 읽을 것
- docs\02-데이터-명세와-콘텐츠-계획.md 1~2장(공통 규칙과 덱별 스키마), 4장(파이프라인)
- 기존에 만든 파일: 〈파일 경로, 예: src\data\words\n5.ts〉 (중복을 피하려고 id 목록을 먼저 뽑아)

# 단어 선정 기준 (words)
- 일상 회화에서 자주 쓰이고 해당 JLPT 수준(비공식 구분)에 맞는 단어. 품사를 고르게(명사 약 45%, 동사 약 25%, 형용사 약 15%, 부사·기타 15% 안팎을 목표로 하되 억지로 맞추지 마).
- 이미 있는 id 와 겹치지 않게. 동음이의어는 id 를 `표기#읽기` 로 구분.
- 고유명사·실존 인물·상표·성적·폭력적·정치·종교 논쟁 낱말은 제외. 술·담배·약물·폭력 관련 낱말이 꼭 필요하면 개수를 최소로 하고 `flag: "sensitive"` 를 달아 목록으로 보고해(연령 등급 설문용).
- 외부 목록(JMdict, 커뮤니티 JLPT 목록 등)을 참고했다면 이름·확인한 날짜·조건을 docs\LICENSES-RESEARCH.md 에 추가하고, 그 목록의 항목을 **그대로 복사하지 말고** 직접 선정·작성해.

# 항목 작성 규칙
- 스키마 필드 전체를 채워(reading, exReading, exKo, level, style, blank(가능한 경우), note(문형)).
- 예문: 그 단어가 **자연스럽게 쓰인** 일상 문장. 8~40자, 해당 레벨 수준의 문법과 어휘만 사용(예문 안의 다른 단어도 같은 레벨 이하가 되도록), 존댓말(です・ます) 기본.
- 읽기: 히라가나(가타카나 단어는 가타카나 그대로). 조사 は・へ・を 는 표기 그대로 가나로.
- 한국어 뜻: 짧고 자연스러운 한국어. 여러 뜻이 있으면 쉼표로 3개 이내, 가장 흔한 뜻부터. 직역투 금지. 예문 해석은 해요체 구어.
- blank: 예문 안에서 단어가 활용된 **정확한 부분 문자열**. 활용형이 애매하면 blank 를 넣지 마.
- 문형(patterns): front 에 접속 틀(〜ておく), back 에 뜻, note 에 접속 규칙 한 줄(동사 て형 + おく 등). 인사·관용 표현은 tag 를 "표현" 으로.
- 가나(kana): 문자, 한글 독음(대략), 예 단어 1개(읽기=표기, 한국어 뜻). 한글로 정확히 옮길 수 없는 문자(う, ふ, つ, ん, 장음·촉음 등)는 note 에 한 줄 설명.
- 모르는 것을 지어내지 마. 읽기·뜻에 확신이 없으면 그 항목을 빼거나 `review: true` 를 달아 목록으로 보고해.

# 출력
1. 데이터 파일에 바로 쓸 수 있는 TypeScript 배열(스키마 타입 그대로)로 파일에 저장. 배치마다 파일을 나누거나 같은 파일에 이어 붙이되 id 중복이 없어야 해.
2. 자동 검증 스크립트(scripts\validate-content.cjs)를 실행해 통과시켜. 스크립트가 아직 없으면 docs\02 4장 ③의 항목(스키마, 중복, 문자 종류, blank 포함, 읽기가 가나만인지, 길이, 금지어)을 구현해서 먼저 만들어.
3. 읽기 대조: 형태소 분석기(Node 용 kuromoji 등 설치 가능 여부 확인)로 reading·exReading 을 자동 대조하고 불일치 목록을 reports\reading-mismatch-〈덱〉-〈레벨〉.md 로 저장해. 정상적인 다의 읽기 불일치와 실제 오류를 구분해서 적어.
4. 보고: 만든 개수, id 중복 0 확인, sensitive/review 표시 항목 목록, 읽기 불일치 요약, 아직 검수하지 않은 부분.
