# 기술 변경 목록 (영어 앱 → 일본어 앱)

영어 앱 저장소 `D:\personal_project\English-Sentence`를 복사해 시작한다. 아래는 파일별로 무엇을 바꾸는지의 지도다. 영어 앱의 현재 구조 기준이며, 복사한 뒤 실제 파일을 열어 확인한다.

## 5. 음성 생성 (`scripts/generate-audio.cjs`)

- 읽는 대상(`collectItems`)을 일본어 데이터에 맞게 변경(표제어·예문·문장 정답·대화문 줄·용어집).
- Google Cloud TTS 요청의 `languageCode`를 `ja-JP`로, 음성 이름을 `ja-JP-Chirp3-HD-*` 중에서 선택(`--list-voices`로 확인).
- 읽기 보정(`audio-overrides.json`)과 `<sub>` SSML 지원, 읽기 기준 합성 옵션(`--word-source=reading|surface`).
- 샘플 모드(`--sample`)로 대표 문구를 먼저 청취, 속도·품질 확인.
- `.env`(`GOOGLE_CLOUD_PROJECT`, `TTS_VOICE`, `TTS_VOICE_ALT`, `TTS_CHAR_LIMIT`, `GCLOUD_PATH`)는 새로 만들고 키를 채팅에 붙이지 않는다. gcloud ADC 로그인은 사용자가 직접.
- 결과 mp3와 `src/audio/manifest.ts`는 영어 앱과 같은 형식(자동 생성, 직접 수정 금지).

## 7. 검증

- `npm run typecheck`, `npx expo-doctor`, iOS 번들(`npx expo export --platform ios`).
- 데이터 검증 스크립트(스키마·중복·읽기·blank·표현 설명), 저장값 검증 스크립트(깨진 값·옛 형식), 퀴즈 스크립트(수만 문제 생성해 보기 중복·정답 위치·빈칸 일치), 음성 manifest 점검(읽는 문구 전부 파일 존재).
- 웹에서 화면 확인은 `npm run web`(로컬만). 작은 화면(320×568, 375×667)과 글자 크기 최대에서 후리가나 줄 포함 레이아웃 확인.
- 실기기: 무음 모드·비행기 모드 음성, 알림, 한 손 조작(영어 앱 점검표 `docs/release-guide.md` 참고).

## 8. 작업 순서 팁

1. **가나 덱 + 샘플 단어 20장**으로 전체 흐름(카드·퀴즈·음성·설정)이 도는 가장 작은 앱을 먼저 만든다.
2. 그다음 스키마·퀴즈·검색을 일본어에 맞게 완성하고, 마지막에 콘텐츠를 대량으로 채운다.
3. 콘텐츠를 채우는 동안에도 앱은 항상 빌드·실행되는 상태를 유지한다(데이터 파일 단위로 추가).
